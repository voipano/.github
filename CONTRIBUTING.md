# Contributing to Voipano

Thank you for your interest in improving Voipano's open-source projects.

We welcome reproducible bug reports, documentation improvements,
thoughtful feature requests, and focused code contributions.

## Before contributing

- Read the repository README and existing documentation.
- Search open and closed issues to avoid duplicates.
- Confirm that your proposal applies to the specific SDK or project.
- Open an issue for significant changes before starting implementation.

## Reporting bugs

Use the repository's Bug Report issue template.

Include:
- The affected SDK and version.
- Your runtime and operating environment.
- Clear steps to reproduce the issue.
- Expected and actual behavior.
- A minimal reproducible example, when possible.

Never include API tokens, passwords, customer data, call recordings,
or confidential infrastructure information in public issues.

## Suggesting improvements

Use the Feature Request template.

Explain the problem, the proposed behavior, and the expected
benefit. Keep proposals focused and grounded in real use cases.

## Pull requests

1. Fork the relevant repository and create a focused branch.
2. Follow its existing coding conventions and architecture.
3. Add or update tests when changing behavior.
4. Update documentation when public behavior changes.
5. Run the repository's documented checks before submitting.
6. Explain the purpose and scope of the change in the PR.

Please avoid unrelated formatting changes, generated files,
and unnecessary dependencies.

Maintainers may request revisions before accepting changes.

## Security

Do not disclose suspected security vulnerabilities in public issues.

Follow the affected repository's SECURITY.md for responsible
and private vulnerability reporting.
